# Relay — id_effect reference app

A chat across three (or more) nodes with presence, built only through `id_effect_kit` on the
one-call surface (ADR 0014). It is the 0.12 KPI: the CI job `reference-relay` runs it over
HTTP/3 and over WebSocket, with the generated TypeScript client and with Chromium, and once
more with UDP blocked.

| Piece | How |
|---|---|
| Rooms | channels topics (`id_effect_kit::rpc::channels`); a join is the subscription `Relay.join`, admitted by `MembersOnly` (room members in PostgreSQL; deny by default) |
| Presence | each node's hub shares its members over the mesh; a node that goes away loses its members at once |
| Messages | the two-way stream `Relay.chat` (or the mutation `Relay.send`): appended to the room's stream in the event log, then published on the room's channel |
| History | the subscription `Relay.history` on the PostgreSQL event log: the cursor is the event position, so a client that reconnects resumes with no gap and no repeat |
| Node to node | mesh RPC (`RelayPeer.status`, guarded by `MeshPeerGuard`), asked by `Relay.cluster` |
| One port | one QUIC endpoint per node routes `h3` (HTTP/3, WebTransport) and `idm/1` (the mesh, mutual TLS with pinned node certificates); TLS on TCP on the same port number serves HTTP/2, HTTP/1.1 and the RPC WebSocket, with `Alt-Svc` |
| Access | every procedure is guarded: a signed-in user (bearer JWT, `Relay.*`) or a verified mesh node (`RelayPeer.*`); nothing is public |
| Posture | under `prod` every probe passes with zero accepted risks; a failed probe stops the node before it binds a socket |

## Clients

- **Rust**: the generated `RelayClient` over HTTP (`HttpTransport`, HTTP/3 with the platform's
  `Http3Client`) and over the RPC WebSocket (`WsClient`).
- **TypeScript**: `web/src/rpc`, generated by `id-effect rpc gen ts --contract rpc.contract.json
  --out web/src/rpc`; `web/tests/relay.test.ts` runs it under Deno.
- **Browser**: `web/index.html` and `web/app.js`, served by every node: WebTransport when the
  browser and the network allow it, else the RPC WebSocket. Browsers cannot set an
  `Authorization` header on either, so the token rides in the `access_token` query parameter of
  `/rpc/ws` and `/rpc/wt` only (the node moves it into the header and strips it from the URI).

## Running a node

```bash
RELAY_NODE=a@relay RELAY_BIND=0.0.0.0:8443 \
TLS_CERT_FILE=cert.pem TLS_KEY_FILE=key.pem \
RELAY_MESH_CERT_FILE=mesh.pem RELAY_MESH_KEY_FILE=mesh-key.pem \
RELAY_MESH_TRUSTED=<sha256 of each node's mesh certificate, comma-separated> \
RELAY_MESH_COOKIE=<at least 32 bytes> RELAY_ORIGINS=https://chat.example \
RELAY_TOKEN_SECRET=<at least 32 bytes> RELAY_TOKEN_ISSUER=https://id.example \
RELAY_DATABASE_URL=postgres://relay@db/relay RELAY_PEERS=10.0.0.2:8443,10.0.0.3:8443 \
ID_EFFECT_PROFILE=prod cargo run -p relay
```

`src/config.rs` lists every variable.

## Tests

```bash
ID_EFFECT_REQUIRE_DOCKER=1 ID_EFFECT_REQUIRE_BROWSER=1 ID_EFFECT_REQUIRE_DENO=1 cargo nextest run -p relay
UPDATE_GOLDEN=1 cargo nextest run -p relay -E 'test(=relay_contract_check_passes)'  # contract + TS client
```

PostgreSQL runs in the tests' own container (never `DATABASE_URL`). Without Docker the tests
print `SKIP`, unless `ID_EFFECT_REQUIRE_DOCKER=1`.

The library is written against the kit:

```rust
use relay::api::{RelayService, valid_room};

assert!(valid_room("general"));
assert_eq!(RelayService::NAME, "Relay");
```
