## Security — ADR 0013 applied to the call surface

Every new surface follows ADR 0013 (`docs/adrs/0013-secure-by-default.md:55-66`): deny by default,
finite limits, every weakening a named `dangerous_*` opt-out recorded by
`id_effect::observability::posture::record_dangerous`, and a prod posture probe. The design document's
S1–S10 labels map to ADR 0013's R1–R10 as below.

| Threat | Default | ADR 0013 rule | Enforcement point (mechanical) | Leaf |
|---|---|---|---|---|
| Unguarded procedure | `#[rpc::service]` refuses a procedure without `#[public]` or `#[guard(G)]`; the low-level `RpcGroup` uses the same typestate as H8 routes | R1 | compile-fail `r1_rpc_procedure_without_access_decision`; runtime `rpc_unregistered_tag_is_404_problem` | r12-e12-1-macro, r12-e12-1-promote |
| Batch amplification | ≤ 50 calls, ≤ 1 MiB body; a batch is charged N calls by the rate limiter | R4 | `r4_batch_over_limit_rejected_413`, `r4_batch_charges_n_rate_limit_tokens` | r12-e12-1-batching |
| Stream / connection exhaustion | streams per connection, frame size, message rate, idle timeout and heartbeats bounded; QUIC stream credits and idle timeout finite | R4 | `r4_ws_streams_per_connection_capped`, `r4_ws_frame_over_max_closes_1009`, `r4_quic_limits_finite_by_default` | r12-e12-2-axum-ws-sse, r12-e12-2-rpc-ws-sse, r12-e12-3-quic-endpoint |
| Cross-site WebSocket hijacking | `Origin` checked on upgrade (WebSocket and WebTransport CONNECT) against an allowlist; empty list refuses every browser origin | R9 | `r9_ws_upgrade_from_foreign_origin_refused`, `r9_webtransport_connect_from_foreign_origin_refused`; `dangerous_any_origin` recorded | r12-e12-2-axum-ws-sse, r12-e12-3-webtransport |
| CSRF on cookie-authenticated RPC | mutations need `Content-Type: application/json` (or postcard) and the `x-rpc` header; the 0.11 CSRF layer applies | R9 | `r9_rpc_mutation_without_custom_header_refused`, `r9_rpc_form_content_type_refused` | r12-e12-1-kinds |
| QUIC amplification / spoofing | address validation (Retry) on; quinn's anti-amplification limit | R4, R8 | `r4_quic_retry_on_by_default`; posture probe "quic retry on" | r12-e12-3-quic-endpoint, r12-w6-kit-template |
| 0-RTT replay | 0-RTT off; `dangerous_allow_zero_rtt_for_queries()` allows it for `query` procedures only, never mutations | R1, R10 | compile-fail `r10_zero_rtt_on_mutation`; `zero_rtt_off_by_default`; opt-out recorded | r12-e12-3-h3-server, r12-e12-5-fuzz-security |
| Resume hijack | resume session ids are 128-bit random and bound to the authenticated principal | R1 | `resume_under_another_principal_refused` | r12-e12-2-bidi-resume |
| Hostile payloads | Schema decode at the boundary; size caps before buffering; fuzz targets on every new decoder | R4 | ≥ 5 fuzz targets (r12-e12-5-fuzz-security) | decoders in their leaves |
| Error leakage | typed errors are the contract; defects become `InternalError { id }` with the correlation id only | R3 | `defect_becomes_internal_error_without_message` | r12-e12-1-kinds |
| Channel join | joining a topic goes through a `JoinPolicy`; default denies | R1 | `channel_join_denied_by_default_policy` | r12-e12-2-channels |
| Operator surfaces | `/rpc/openapi.json`, `/rpc/asyncapi.json`, `/rpc/_contract` closed in prod unless guarded | R7 | `r7_rpc_docs_closed_in_prod` | r12-e12-4-openapi-asyncapi |
| Dev certificates in prod | the `id-effect dev` certificate is refused by the prod profile | R10 | `posture_prod_refuses_dev_certificate` | r12-w6-kit-template |

**Leaf most likely to be wrong:** `r12-e12-3-quic-endpoint`. It moves 0.11's certificate code across
crates, adds a cross-crate dependency (node → platform), and must keep mutual TLS intact on an endpoint
whose handshake cannot require client certificates for one ALPN only. If D7's post-handshake rule is
unsound, or the move breaks the 0.11 tests, the Relay, the HTTP/3 server and dist.tls all rework.

**What would make the plan misconceived:** the belief that one QUIC port for both the public HTTP/3
surface and the mesh is worth having. If the owner (or the assessor) treats "mTLS checked after the
handshake" as weaker than dist.tls#4, or browsers' certificate prompts make the shared shape unusable on
public ports, then "one endpoint with ALPN routing" (E12.3) reduces to "one endpoint type, two ports",
and D6/D7 should flip to separate endpoints by default (Open question 5).
