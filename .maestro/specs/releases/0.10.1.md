# Release 0.10.1 — security patch

Source: the Secure by Default review (2026-10-18, release/0.10.0 @ 5002d918) and
PLAN-OF-PLANS §5 T11 E11.1, §6 row 0.10.1. Scope is fixed: the 13 findings below. H8 (deny-by-default
routing) changes the API and is 0.11 (E11.2).

## Patch-release rules

- 0.10.1 must be semver-compatible with 0.10.0. Add items; do not remove or re-sign them.
- A stricter default is allowed when it closes a finding. It needs an opt-out with `dangerous` or
  `insecure` in its name, a doc comment that says what it re-opens, and a CHANGELOG entry.
- Wire changes to the mesh handshake bump its protocol version. 0.10.0 and 0.10.1 nodes refuse each
  other with a clear `VersionMismatch` error. The CHANGELOG says so.

## Findings

| ID | Finding | Evidence | Fix |
|---|---|---|---|
| H1 | Per-IP rate limiting cannot work: `serve()` drops connection info, so `peer_ip()` is always `None` and every client shares one bucket. | `id_effect_axum/src/server/lifecycle.rs:186,237`; `middleware/rate_limit.rs:178-185,245-249` | Serve with `into_make_service_with_connect_info::<SocketAddr>()`; add a `ClientIp` extractor with a trusted-proxy list that parses `X-Forwarded-For` from the right, skipping trusted hops. |
| H2 | The Ledger's login limiter trusts the first `X-Forwarded-For` entry, which the client controls. | `examples/reference/ledger/src/app.rs:463-474` | Use `ClientIp` with the trusted-proxy list from config (empty by default). |
| M1 | No header-read timeout, keep-alive limit or connection cap on the server (slowloris, connection exhaustion). | `id_effect_axum/src/server/lifecycle.rs:186-193`; `bootstrap.rs:28-34` | A hyper accept loop (hyper-util) with a header-read timeout (default 10 s), a keep-alive limit and a connection semaphore (default 10,000), all configurable. |
| H3 | QUIC accepts any server certificate unless roots are set; TCP is plaintext. | `id_effect_node/src/transport/quic.rs:60,247-254`; `transport/tcp.rs:1-5` | QUIC fails to build without roots or a pinned certificate fingerprint; `dangerous_accept_any_server_cert()` is the explicit opt-out. TCP logs a startup warning naming the insecurity (feature gate in 0.11). |
| H4 | The cookie proof covers only the nonce and node name, not the TLS channel, so a lured node's proof can be relayed. | `id_effect_node/src/handshake.rs:31-36,125-133` | Mix a TLS exporter secret (RFC 5705/8446 `export_keying_material`, label `EXPORTER-id-effect-mesh`) into the MAC on QUIC; on TCP, mix both peers' nonces and names in both directions. Regression test: a relayed proof fails. |
| M9 | No handshake timeout; 16 MiB frames before auth; empty cookie accepted; 64-bit nonce. | `id_effect_node/src/session.rs:46-53`; `transport/tcp.rs:65-70`; `handshake.rs:27-29` | 5 s handshake timeout, 4 KiB frame cap before auth, cookie ≥ 32 bytes (config error otherwise), 128-bit nonce. |
| H5 | No failed-login throttling or lockout in `BasicAuth` or the login flows. | `id_effect_auth/src/basic.rs:178-201` | `LoginThrottle` keyed per account and per IP with exponential backoff, in-memory store (trait so pg/redis follow), on by default in `BasicAuth` and the account login flow; throttle before hashing. |
| H6 | No limit on TOTP attempts. | `id_effect_auth/src/totp.rs:20-21` | Failure counter with lockout after 5 failures per step window, reset on success. |
| H7 | `JwtVerifier` accepts any `iss` and `aud` unless configured. | `id_effect_auth/src/jwt.rs:536-544` | Verification fails with a typed error when no issuer and audience are configured; `any_issuer_dangerous()` / `any_audience_dangerous()` opt out. |
| M15 | JWKS body read unbounded, https not enforced, redirects followed; HMAC keys of any length. | `id_effect_auth/src/jwks.rs:254-257`; `jwt.rs:120-122,631-634` | 1 MiB body cap, https only (http allowed only for loopback in tests), no redirects; HMAC keys < 32 bytes rejected. |
| M20 | Argon2id at 19 MiB with no concurrency cap: 100 parallel logins claim ~1.9 GiB. | `id_effect_auth/src/password.rs:43-47` | A semaphore (default 2 × available parallelism) around hashing and verifying; when full, wait up to a bound then fail with a typed `Busy` error. |
| L4 | `BasicAuth` does not cap password length. | `id_effect_auth/src/basic.rs:189` | Reject passwords over 256 bytes before hashing. |
| M2 | The HTTP client reads the whole body into memory before checking `max_body`. | `id_effect_platform/src/http/mod.rs:392-398` | Enforce the cap while streaming (and on `Content-Length` up front). |
