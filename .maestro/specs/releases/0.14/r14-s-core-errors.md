# r14-s-core-errors

Leaf of `.maestro/specs/releases/0.14.0.md`, section "E13.1 — Sweep". The release spec's row is binding;
this file exists so Maestro can track the leaf as its own task.

Wave 0 head. Blocked by: nothing (release/0.14.0 at v0.13.0). Blocks: r14-s-core-runtime (wave 1;
shares crates/id_effect `lib.rs`, CHANGELOG and the kernel crate), r14-s-parallel-supervision (wave 2),
r14-x-level-audit. (r14-s-core-di edits no file under crates/id_effect/src; see its spec.) Within crates/id_effect/src this leaf owns only
`failure/{union,trace,cause,mod}.rs`, `kernel/cause.rs` (`cause_from_panic`) and `kernel/runloop.rs`
(`Runloop::poll`); r14-s-core-runtime takes `kernel/resource.rs`, `race.rs` and `coordination/*`;
r14-s-parallel-supervision takes `compute/*` and `observability/runtime_metrics.rs`.

Defaults the owner may overturn: (1) the method is named `catch_tag` for Effect.ts parity (Rust has no
tags; the "tag" is the arm type); `LocalEffect` gets no `catch_tag` in this leaf. (2) The
right-arm `From` caveat of core.typed-effect#4 (tests/ui/gallery/or_error_right_arm.rs) is not
changed. (3) Typed failures get traces only through the opt-in `traced()` (changing `Cause::Fail(E)`
would break every match on `Cause`); defects get them always. (4) A panic carries the span trace but
not the panic-site backtrace (that needs a process panic hook; a non-goal here). The kernel hot path is
untouched: `catch_tag` is `catch` plus a match, and the runloop change is on the panic path only.
