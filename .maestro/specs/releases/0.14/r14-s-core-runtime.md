# r14-s-core-runtime

Leaf of `.maestro/specs/releases/0.14.0.md`, section "E13.1 — Sweep". The release spec's row is binding;
this file exists so Maestro can track the leaf as its own task.

Wave 1. Blocked by: r14-s-core-errors (same crate; it edits `kernel/runloop.rs` and `kernel/cause.rs`,
which this leaf only reads). Blocks: r14-s-parallel-supervision (wave 2, same crate), r14-w-warden-mesh
(promotes core.race and conc.coordination), r14-e-benches (writes the 1M-fiber bench budget from this
leaf's README section), r14-x-level-audit. Within crates/id_effect/src this leaf owns
`kernel/resource.rs`, `race.rs`, the audited `coordination/*` files and the two streaming files above;
r14-s-core-di (wave 1) edits no file under crates/id_effect/src, and r14-s-testing (wave 1) must keep
to `crates/id_effect/src/testing/*`, which this leaf does not touch.

Defaults the owner may overturn: (1) conc.coordination#8 is met in code at HEAD; the leaf adds the
evidence (tests + docs) rather than new behaviour, and `Semaphore::acquire_n(n)` with `n` larger than
the permits that will ever exist keeps suspending (documented; a semaphore has no fixed total). (2) The
1M test runs in the normal nextest suite; if CI memory makes it flaky the leaf reports the number and
moves the test to a `slow` nextest profile run by bench.yml rather than lowering the count. (3)
`on_interrupt` / `on_exit` / `race_with` / `disconnect` are on `Effect` only, not `LocalEffect`.
Non-goals: brokers and id_effect_messaging channels (other leaves), a panic hook, `race_with` over more
than two effects.
