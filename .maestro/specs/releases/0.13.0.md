## The Pipeline reference app (D1)

PLAN-OF-PLANS names "Pipeline" in §6 (0.13 exit KPI), E10.4 and E13.2 but never defines it. This plan
defines it from the slot's epics (owner may overturn, Open question 1); r13-t0-adr0015 writes the
definition into ADR 0015 and PLAN-OF-PLANS §5 T9.

**Pipeline** (`examples/reference/pipeline`, package `pipeline`, tier `example`, `publish = false`,
built only through `id_effect_kit`) is a multi-tenant document-intake pipeline and its back office:

1. **Ingest:** documents arrive by RPC mutation or upload (storage) for a tenant; a job per stage
   (`id_effect_jobs`).
2. **Extract:** an AI model turns text into a typed `Extraction` (structured output decoded through
   `Schema`, ai.llm #4).
3. **Classify:** a bounded tool loop calls `lookup_source` and `list_labels` (typed tools, #3, #8) and
   attaches `Label`s.
4. **Embed:** embeddings (#5) flag near-duplicates within the tenant (bounded candidate set).
5. **Review:** reviewers work in the admin generated by `id-effect generate admin` (web.admin) and an
   htmx + maud review queue (web.ui), in English or German (eco.i18n; Accept-Language plus a per-user
   override).
6. **Publish:** an `after_update` lifecycle hook (data.orm #7) writes `DocumentPublished` to the
   outbox; an RPC subscription shows live status.
7. **Agents:** an MCP server exposes `search_documents` / `get_document` to outside agents (guarded,
   Origin-checked); an MCP client enriches documents from a fixture MCP tool server (#6).

Data model: `Source` 1:N `Document` N:M `Label` (join table `document_labels`), `Document` 1:N
`Extraction`, all tenant-scoped; tenant `acme` (en) shares the main database, tenant `globex` (de) is
routed to its own database (eco.tenancy #8, margin). AI in CI is deterministic (D8): a scripted model
plus wiremock'ed OpenAI and Anthropic adapters; no API key exists in CI.

The name collides with `id_effect_resilience::Pipeline` (a policy type); the book and README always
say "the Pipeline reference app".

## Epics, checks and leaves

Leaf slugs are `r13-<epic>-<name>`; each has a file in `.maestro/specs/releases/0.13/` and becomes a
Maestro task. **Rules for every leaf:** it names the crate paths it owns (disjoint within a wave) and
its ADR 0010 tier; it passes its gate plus `cargo clippy -p <crate> --all-targets --all-features --
-D warnings`; coverage of each crate it touches ≥ 96 % regions and of its new code ≥ 96 % regions
(`cargo llvm-cov nextest -p <crate> --all-features --summary-only --fail-under-regions 96`; examples
are outside the workspace gate, 0.12 F54); public API denies `missing_docs` and adds a CHANGELOG line;
a semver break adds its section to `docs/MIGRATION-0.13.md`; every `dangerous_*` API records itself
with `posture::record_dangerous` and is listed by `scripts/check-dangerous.sh`; book chapters live under
`crates/id_effect/book/src/` and are compiled by `examples/book-snippets` (K5). Live tests read
`ID_EFFECT_REQUIRE_PG=1` / `ID_EFFECT_REQUIRE_DOCKER=1`, fail rather than skip, and start their own
container through `id_effect_test` (never the ambient `DATABASE_URL`). `<pg>` = `ID_EFFECT_REQUIRE_PG=1
cargo nextest run`; `<docker>` = `ID_EFFECT_REQUIRE_DOCKER=1 cargo nextest run`. Gates run with `TMPDIR` under `/data`. New dependencies are exact-pinned where the
crate is pre-1.0 (maud, fluent-*, htmx file) and pass `cargo deny check`.

Tiers (ADR 0010 / ADR 0012): `core` = strict bar (id_effect); `runtime` = strict (id_effect_node);
`integration` = standard (id_effect_{sql,axum,authz,platform,rpc,events,tool,kit,ai,admin,i18n,
proc_macro}); `example` = builds and tests (reference apps, recipes, book-snippets,
security_compile_fail). Crates already at `platform` (ADR 0012 rule 4) keep the integration bar.
