## Decisions (resolved by the owner 2026-10-16, before EXECUTE)

D1: re-target to 50. D2: adopt the rule as method 2.1 (METHOD §7.4, leaf `method-2-1-process-rows`).
The 0.8 plan was approved with "start wave 1".

- **D1 — `data.jsonschema` at 0.8.** Its 0.8 target (75 = 6/8 checks) needs OpenAPI from routes and a
  docs UI, which PLAN-OF-PLANS slots for 0.9 (E2.3 OpenAPI, E4.1–E4.2). Without them 0.8 reaches 4/8
  (JSON Schema export, same schemas, annotations, constraints) = 50.
  *Recommendation:* re-target 0.8 to 50 and keep 75+ at 0.9 (−0.8 on the 0.8 target E); the
  alternative is pulling a minimal OpenAPI generator into 0.8 (+L effort).
- **D2 — level of process rows.** For `eco.license`, `sec.supply`, `eco.stability`, `eco.backing`
  the level caps the score (eco.license is at `published`, cap 49, so MIT + LICENSE file alone still
  scores 49, not the 100 target), while every competitor is judged `production` on these rows.
  *Recommendation:* add one METHOD §7.4 rule (method 2.1): for a process row the level is
  `production` when each met check is a committed artifact (file, CI job or published policy), as for
  competitors; otherwise `published`. Re-scores only these rows; targets unchanged.
