## The Warden reference app (D1)

`examples/reference/warden` (publish = false, tier example), built only through `id_effect_kit`: a
supervised, durable, capability-typed agent runtime. It is the reference app for what Ledger, Relay and
Pipeline do not use: AI agents, a real broker and durable workflows.

1. **Agent runs are durable workflows.** Each run is an `id_effect_workflow` workflow with Postgres
   history. Its steps are model calls (`id_effect_ai`, `ScriptedModel` plus the wiremock vendor fixtures)
   and tool calls. A run survives a process restart and resumes from history.
2. **Tools are capability-typed.** A tool's type declares the capabilities it may use. A hostile prompt
   cannot call an unlisted tool, and a tool cannot reach a capability it did not declare (compile-time
   plus a runtime test).
3. **Lifecycle and budgets.** The agent lifecycle (queued → running → waiting → done/failed/cancelled)
   is an `id_effect_fsm` machine. A per-tenant token/tool budget ledger is shared state under STM.
4. **Work intake.** Tasks arrive on Redis Streams and on Kafka (the new `id_effect_kafka`), with
   inbox deduplication so a redelivered message never repeats a tool effect, and through jobs/cron.
5. **Supervision and the mesh.** Three nodes form a mesh (membership, remote calls, key-based placement
   of agents). A supervisor tree per node restarts crashed agents, with significant children and
   `max_children` limits. When a node is killed, its agents are re-placed and resume.
6. **Operations.** `/_console` (fiber dump, profiling) behind auth, runtime fault toggles and a
   toxiproxy between nodes in the chaos tests, a prod posture with zero accepted risks, and CI job
   `reference-warden` (Postgres + Redis + Kafka containers).

## Epics, checks and leaves

Leaf slugs are `r14-<kind>-<name>` (t0 = governance, s = sweep, p = promote, w = Warden, f = 0.13
follow-up, e = proof, x = exit); each has a file in `.maestro/specs/releases/0.14/` and becomes a
Maestro task. The leaf file holds the binding detail (Owns, tests, gate). **Rules for every leaf** are
as in 0.13: it names the paths it owns (disjoint within a wave) and its ADR 0010 tier; it passes its
gate plus `cargo clippy -p <crate> --all-targets --all-features -- -D warnings`; coverage of each crate
it touches ≥ 96 % regions (`cargo llvm-cov nextest -p <crate> --all-features --summary-only
--fail-under-regions 96`; examples outside the workspace gate); public API denies `missing_docs` and
adds a CHANGELOG line; a semver break adds its section to `docs/MIGRATION-0.14.md`; every `dangerous_*`
API records itself with `posture::record_dangerous` and is listed by `scripts/check-dangerous.sh`; book
chapters live under `crates/id_effect/book/src/` and are compiled by `examples/book-snippets` (K5). Live
tests read `ID_EFFECT_REQUIRE_PG=1` / `ID_EFFECT_REQUIRE_DOCKER=1`, fail rather than skip, and start
their own container through `id_effect_test`. New pre-1.0 dependencies are exact-pinned and pass
`cargo deny check`.
